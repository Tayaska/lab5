# Трансформери та платформа Hugging Face

## Платформа Hugging Face

Hugging Face — це платформа для обміну моделями машинного навчання, наборами даних і демонстраційними застосунками. На ній розміщено сотні тисяч попередньо навчених моделей для класифікації тексту, перекладу, генерації тексту, розпізнавання зображень і мовлення. Для завантаження деяких моделей і наборів даних потрібен токен доступу (Access Token), який створюється в налаштуваннях облікового запису (Settings → Access Tokens). Для читання достатньо токена типу Read.

Основні бібліотеки: transformers — для роботи з моделями, datasets — для завантаження наборів даних, huggingface_hub — для авторизації та роботи з репозиторіями.

## Архітектура трансформер

Трансформер — це архітектура нейронної мережі, в основі якої лежить механізм уваги (self-attention). Механізм уваги дозволяє моделі для кожного слова враховувати всі інші слова речення і визначати, які з них найважливіші для розуміння контексту. Трансформери обробляють усі слова тексту паралельно, тому навчаються швидше за рекурентні мережі.

**BERT** — модель-кодувальник на основі трансформера, яка добре підходить для задач розуміння тексту: класифікації, пошуку іменованих сутностей, відповідей на запитання. **DistilBERT** — полегшена версія BERT, отримана методом дистиляції знань: вона приблизно на 40 % менша і на 60 % швидша, але зберігає близько 97 % якості BERT.

## Токенізація

Токенізатор перетворює текст на послідовність токенів — слів або частин слів — і кожному токену зіставляє номер у словнику моделі (input_ids). Додатково формується маска уваги (attention_mask), у якій одиниця означає реальний токен, а нуль — доповнення (padding). Моделі сімейства BERT додають службові токени: [CLS] на початку тексту і [SEP] у кінці.

Важливі параметри токенізатора:
- **max_length** — максимальна кількість токенів, яку отримає модель. Для BERT і DistilBERT максимум становить 512 токенів.
- **truncation=True** — обрізати текст, довший за max_length. Без цього параметра надто довгий текст спричинить помилку.
- **padding** — доповнювати короткі тексти до однакової довжини в межах пакета.

Якщо max_length занадто малий, модель бачить лише початок тексту і може втратити важливу інформацію, що знижує точність. Оптимальне значення max_length вибирають з урахуванням розподілу довжини текстів у наборі даних, наприклад так, щоб воно перевищувало довжину 95–99 % текстів.

## Pipeline

Функція pipeline з бібліотеки transformers — це найпростіший спосіб використати модель. Наприклад, pipeline("text-classification", model="назва-моделі") сам виконує токенізацію, передає дані в модель і перетворює вихід на назву класу з імовірністю (score).

## Ручне використання моделі

Для більшого контролю модель і токенізатор завантажують окремо: AutoTokenizer.from_pretrained і AutoModelForSequenceClassification.from_pretrained. Модель повертає логіти — по одному числу на кожен клас. Функція softmax перетворює логіти на ймовірності, а клас із найбільшим значенням (argmax) є прогнозом. Відповідність номерів класів їх назвам зберігається в model.config.id2label.

## Великі мовні моделі для класифікації

Великі мовні моделі (LLM), такі як GPT, Gemini або Claude, можуть класифікувати текст без додаткового навчання (zero-shot) — достатньо описати класи в запиті (промті) і задати формат відповіді. Такий підхід гнучкий, але повільніший і дорожчий, ніж спеціалізована модель, і результати можуть відрізнятися між запусками. Спеціалізована модель, донавчена на конкретному наборі даних, зазвичай точніша саме на ньому.
